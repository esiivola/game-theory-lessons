# Top trading cycles

<p class="lead">When goods must be reassigned without money and everyone starts with something, top trading cycles is the answer. Each person points to whoever owns their favourite item; wherever the pointing forms a cycle, that cycle trades and leaves. The result is efficient, in the core, and impossible to game.</p>

<Section id="why">
## Why did that happen?

<Callout kind="ask">
A cycle is a chain of wants that closes on itself: 1 wants 3's house, 3 wants 2's, 2 wants 1's. Everyone in that loop can be satisfied at once by rotating the houses around it, and because each got the best house still available to them, no one in the cycle envies anyone. Once a cycle trades and leaves, the rest repeat. Agents whose favourites are already gone simply keep what they have. Nothing rewards misreporting, because your pointing only ever helps complete a cycle that includes you.
</Callout>
</Section>

<Section id="math">
## The math

<DefinitionAside label="top trading cycles">
Each agent owns one object and has strict preferences. Build a graph in which every remaining agent points to the owner of its favourite remaining object. Because every node has exactly one outgoing edge, at least one cycle exists. Every agent on a cycle receives the object it points to, then leaves with it. Repeat on what remains. The allocation is Pareto efficient, is the unique allocation in the core, and the mechanism is strategy-proof.
</DefinitionAside>

With agents $1,2,3,4$ owning $h_1,\dots,h_4$ and the given preferences, round 1 has $1 \to 3$ (owner of $h_3$), $2 \to 1$, $3 \to 2$, $4 \to 3$. The cycle $1 \to 3 \to 2 \to 1$ trades: agent 1 gets $h_3$, agent 3 gets $h_2$, agent 2 gets $h_1$. Agent 4 pointed into the cycle but is not on it, so it waits. Round 2 leaves only agent 4 and house $h_4$, which it takes. Final allocation: $(h_3, h_1, h_2, h_4)$.

Compare with deferred acceptance: in school choice, TTC is efficient but can violate priorities, whereas DA respects priorities (is stable) but is not always efficient. The two mechanisms optimize different things.
</Section>

<Section id="worked">
## Work it out

<WorkedExample title="Find and execute the cycle">
Each agent points to the owner of its top remaining house. Agent 1's favourite is $h_3$, owned by agent 3, so $1 \to 3$. Agent 2's favourite is $h_1$ (agent 1), so $2 \to 1$. Agent 3's favourite is $h_2$ (agent 2), so $3 \to 2$. Agent 4's favourite is $h_3$ (agent 3), so $4 \to 3$.

Follow the arrows: $1 \to 3 \to 2 \to 1$ closes into a cycle; agent 4 points into it but is not part of it. Execute the cycle by giving each member the house it points to: agent 1 takes $h_3$, agent 3 takes $h_2$, agent 2 takes $h_1$. Remove them and their houses. Only agent 4 and $h_4$ remain, so agent 4 keeps $h_4$. No agent could have done better by misreporting, and no coalition can re-trade to improve, so the outcome is both strategy-proof and in the core.
</WorkedExample>
</Section>

<Section id="key">
## Key idea

<Callout kind="key-idea">Top trading cycles reassigns owned goods by rotating them around cycles of mutual demand. The result is efficient, the unique core allocation, and strategy-proof, though scarcity means not everyone gets their first choice.</Callout>
</Section>
