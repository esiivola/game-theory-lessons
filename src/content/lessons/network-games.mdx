# Network and graphical games

<p class="lead">When payoffs depend only on your neighbours, a game lives on a graph. Graphical games make network structure the star: the same simple rule produces very different outcomes on a star, a cycle, or a hub, and local best responses can often find an equilibrium without any global solver.</p>

<Section id="why">
## Why did that happen?

<Callout kind="ask">
The good only needs to be provided once within each neighbourhood. On a star, the hub touches everyone, so if the hub provides, the whole network is covered and every leaf can free-ride. On a cycle, no single node reaches everyone, so providers must be spaced out, one, skip, one, skip, taking three of six. Same incentives, same rule, but the graph's shape sets how many providers are needed and who they are.
</Callout>
</Section>

<Section id="math">
## The math

<DefinitionAside label="graphical games">
A graphical game places players on a graph so that each player's payoff depends only on its own action and its neighbours'. This makes the game compact to describe and often tractable to solve, since local structure can be exploited. In the best-shot public-goods game, a pure Nash equilibrium is exactly a maximal independent set of providers: no two providers are adjacent (that would waste a contribution), and every non-provider has a provider neighbour (or it would rather provide itself).
</DefinitionAside>

Each node's best response: provide if and only if no neighbour provides. In equilibrium the providers form an independent set (none adjacent) that is maximal (every other node is adjacent to a provider). On a star, the hub alone is a maximal independent set, so one node provides and society's cost is $1$. On a six-cycle, a maximal independent set has size $3$ (alternate nodes), so three provide, cost $3$.

Because best responses depend only on neighbours, local update dynamics converge to such an equilibrium without a global computation, one reason graphical games are attractive for large networks.
</Section>

<Section id="worked">
## Work it out

<WorkedExample title="Star versus cycle">
On the star, suppose the hub provides. Every leaf has the hub as a neighbour, so each leaf is content to free-ride (a provider neighbour exists), and the hub, whose only neighbours are non-providing leaves, is content to provide. That is a maximal independent set of size $1$: the whole street served for a cost of $1$.

On the six-cycle, try one provider: some node two steps away has no providing neighbour, so it would rather provide, breaking the profile. Space providers every other node and you get three, an independent set (no two adjacent) that is maximal (every gap node touches a provider). Cost $3$. The identical best-shot rule triples the social cost purely because the cycle has no hub to cover everyone at once.
</WorkedExample>
</Section>

<Section id="key">
## Key idea

<Callout kind="key-idea">In a graphical game, payoffs depend only on neighbours, so network structure drives the outcome. In best-shot public goods, equilibria are maximal independent sets, and a hub can serve everyone while a cycle forces many providers.</Callout>
</Section>
